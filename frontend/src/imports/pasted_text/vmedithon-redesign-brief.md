Redesign the existing VMedithon interface while keeping the existing information architecture and functionality.

The current visual direction is too high-contrast and too neon. Replace it with a **calm, premium biomedical / genomics aesthetic**.

The application should feel like a sophisticated research and clinical decision-support platform — elegant, precise, scientific, and trustworthy.

## 1. Color palette

Use a restrained, low-contrast palette.

Primary background:

* warm off-white / very light cool gray
* approximately #F6F8F7

Secondary surfaces:

* white
* very light gray-green
* subtle translucent surfaces

Primary text:

* deep charcoal rather than pure black

Accent:

* muted teal / deep sage
* approximately #397C78

Secondary accent:

* desaturated blue-green
* approximately #6F9F9B

Optional highlight:

* extremely subtle pale lavender/blue

Avoid:

* bright cyan
* electric blue
* purple neon
* pure black backgrounds
* extremely saturated gradients
* excessive glowing effects
* strong color contrast between every component

The overall palette should feel **soft, sophisticated, and medically credible**.

Use color primarily for hierarchy and interaction, not decoration.

## 2. DNA visualization — completely redesign it

The DNA should NOT look like a glowing sci-fi hologram.

Create a **realistic-looking molecular DNA double helix** with two clearly visible strands.

The helix should contain:

* two continuous curved strands
* realistic connecting base-pair structures between the strands
* many small nucleotide/base-pair connections
* subtle molecular detail
* natural depth
* slight transparency
* soft lighting
* realistic scientific visualization rather than a cartoon icon

Think of a **high-quality molecular biology visualization**, not a neon technology graphic.

### Position

Place the DNA helix along the **side of the screen at a diagonal angle**.

It should travel approximately:

**upper-right → lower-left**

or

**upper-left → lower-right**

depending on whichever composition looks more balanced.

The DNA should occupy roughly 20–30% of the visual composition and remain primarily at the edge of the interface.

Do NOT put the DNA directly behind the main text or form fields.

Do NOT place it vertically in the center.

Do NOT let it dominate the interface.

The user should notice it as a beautiful scientific detail after noticing the actual application.

## 3. DNA animation

Animate the realistic DNA subtly.

The strands should have slow, natural movement suggesting rotation in three-dimensional space.

Base pairs should remain connected while the helix moves.

Add a very subtle traveling light/pulse along the strands.

When the user clicks **Analyze Variant**:

* the DNA briefly becomes slightly more active
* a subtle pulse travels through the helix
* the analysis interface transitions smoothly
* after the result appears, the DNA returns to its calm background motion

Avoid:

* flashing
* rapid rotation
* particle explosions
* excessive glow
* sci-fi energy beams

The animation should feel like **a living molecular structure being analyzed**.

Respect reduced-motion accessibility preferences.

## 4. Overall composition

Use a spacious editorial layout.

Think:

**premium biotechnology laboratory + modern clinical software**

rather than:

**cyberpunk AI dashboard**

Use:

* large whitespace
* clean typography
* thin borders
* subtle shadows
* restrained rounded corners
* elegant cards
* carefully aligned grids
* minimal decorative elements

The interface should breathe.

## 5. Main hero

Use a clean light background.

Heading:

**Variant Intelligence**

Supporting text:

**Transparent evidence-driven analysis for hereditary cancer variants.**

Keep the hero typography dark charcoal and elegant.

Use the diagonal DNA visualization as the primary visual element on one side of the hero.

The DNA should visually balance the typography without competing with it.

## 6. Analysis workspace

Create a large white analysis card with a very subtle border.

Title:

**Analyze a Variant**

Fields:

**Gene**

Placeholder:
`e.g. BRCA1`

**HGVS notation**

Placeholder:
`e.g. c.5266dupC`

Use refined input fields with:

* light borders
* subtle teal focus state
* no heavy shadows
* no neon outlines

## 7. Evidence builder

Create a clean evidence section below the variant inputs.

Title:

**Evidence**

Subtitle:

`Add structured evidence used in the analysis.`

Evidence entries should look like compact scientific records rather than generic form fields.

Each evidence card contains:

* Evidence ID
* Criterion
* Strength
* Direction
* Source
* Reference
* Summary

Use restrained dropdowns and controls.

Primary action:

**+ Add Evidence**

## 8. Analyze button

Use a single strong but understated primary button:

**Analyze Variant**

Use muted teal as the button color.

Hover:

* slightly darker teal
* subtle elevation

Active:

* subtle press animation

Do not use a bright gradient.

## 9. Result visualization

When analysis completes, transition into a clean result section.

Title:

**Analysis Result**

Display the classification prominently but elegantly.

Example:

**Likely Pathogenic**

Use a restrained classification badge.

Support all existing classifications:

* Pathogenic
* Likely Pathogenic
* Uncertain Significance
* Likely Benign
* Benign
* Conflicting
* Insufficient Evidence

Do not rely on color alone.

## 10. Evidence → Rules → Classification visualization

Make the explainability section visually distinctive.

Create a horizontal or vertical scientific flow:

**Evidence**
↓
**Criteria**
↓
**Rule Evaluation**
↓
**Classification**

Use thin connecting lines and small nodes.

The visualization should feel like a **scientific reasoning pathway** rather than an AI flowchart.

Allow individual evidence and rule items to expand.

Show:

* criterion
* strength
* direction
* evidence summary
* source
* provenance/reference
* satisfied rules
* unsupported rules

## 11. Loading state

During analysis:

Show:

**Analyzing variant**

`Evaluating structured evidence and decision rules...`

Use:

* subtle DNA movement at the side
* gentle pulse animation
* understated progress indicator

Keep the loading state calm.

## 12. Empty state

Before analysis:

**Ready for analysis**

`Enter a gene, HGVS notation, and optional structured evidence to begin.`

Use a faint scientific/molecular background detail.

## 13. Error state

Use a calm, professional error design.

Avoid large red panels.

Use:

* subtle warning icon
* concise explanation
* **Try Again** button

## 14. Typography

Use a modern, highly readable sans-serif typeface.

Typography should feel:

* precise
* editorial
* premium
* clinical

Use strong hierarchy but avoid oversized startup-style headings.

## 15. Important visual rule

The DNA is a **supporting visual identity**, not the application itself.

The hierarchy should be:

1. Variant analysis workflow
2. Result
3. Evidence and explainability
4. DNA visualization

The DNA should make the product memorable without distracting from the decision-support workflow.

## Final aesthetic target

The finished interface should look like a premium genomics research product photographed in a modern laboratory:

**soft off-white + charcoal + muted teal + subtle molecular visualization + realistic diagonal DNA helix + generous whitespace.**

Avoid the previous:

* neon aesthetic
* dark cyberpunk background
* excessive gradients
* glowing cards
* oversized central DNA
* abstract DNA icon

The result should feel **calm, credible, scientific, and expensive**.
